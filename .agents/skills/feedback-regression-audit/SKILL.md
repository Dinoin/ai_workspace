# 回饋導向回歸稽核

將單一問題視為可驗證的缺陷模式，而非只修補當前檔案。依實際程式碼、測試與錯誤訊息判斷範圍；不從文件或猜測延伸結論。

## 工作流程

1. 重新讀取問題描述、重現步驟、錯誤輸出、失敗測試與相關程式碼，將問題寫成可搜尋的模式：輸入、條件、錯誤行為與預期結果。
2. 定位直接成因，確認修正點及其資料流、呼叫端或相同抽象層級的實作。
3. 以函式呼叫、相同 API、相同欄位、相同例外處理或相同條件分支等具體結構搜尋同類模式。
4. 逐一區分真正同類缺陷與表面相似但語意不同的結果；每個結論都具備程式碼證據，不直接顯示於回應但使用者需查看時能直接列舉。
5. 為直接缺陷與確認存在的同類缺陷補上最小有效修正，並建立或更新可驗證原問題的回歸測試。
6. 執行與變更範圍相符的既有測試或靜態檢查；若無法執行，明確說明原因與尚未驗證的風險。

## 交付檢核

- 分開列出直接修正、已檢查但無問題的相似位置，以及無法確認的位置。
- 測試必須能在修正前失敗或至少明確覆蓋原始錯誤條件。
- 保留既有例外處理，或補足可預期失敗路徑的錯誤處理。
- 找不到可搜尋模式或缺少重現資訊時，先要求最小必要證據，不假設根因。
