# 管理共用資料的單一來源

先確認資料的所有讀寫端，再依使用範圍選擇唯一擁有者。

## 工作流程

1. 重新讀取相關程式碼，列出資料的定義處、讀取端、寫入端與傳輸邊界；不要僅從文件推測使用範圍。
2. 將資料歸類為跨服務共用或單一服務內部使用。
3. 對跨前端、後端或擴充套件的資料：
   - 將資料定義集中在後端的明確模組或資料來源。
   - 經由 API 提供前端與其他使用端，移除其硬編碼副本。
   - 讓前端在既有 store 或快取機制中保存資料，避免每次使用都重新查詢。
4. 對僅單一服務使用的資料：將值集中在該服務的設定或常數模組，移除散落的重複定義。
5. 僅在無法共用來源的必要情況下保留多端定義，並以繁體中文註解標出所有需要同步的檔案路徑與原因。
6. 搜尋舊值、同義列舉與重複映射，確認所有消費端都已改用唯一來源；保留既有向後相容需求時，明確說明轉換界線。

## 交付檢核

- 說明資料的唯一擁有者與消費端。
- 確認跨服務資料沒有另一份可寫入的硬編碼副本。
- 確認例外的同步註解可直接定位每個關聯檔案。
- 資料範圍或權責無法確認時，先提出問題；不得臆測來源端。
