# 資料庫結構慣例

依目前 schema、migration 與 ORM 定義進行變更。本 Skill 不指定特定資料庫或 migration 工具，須延續專案既有做法。

## 工作流程

1. 重新讀取現有資料表、對應 ORM model、migration 與使用該資料的程式碼，確認實際資料模型與相容性限制。
2. 為每個新增或修改的資料表與欄位撰寫 COMMENT，說明用途、業務意義，以及必要的外鍵或欄位關聯；不要留下沒有業務資訊的空泛描述。
3. 依核心資料優先排列欄位：`id` 或主鍵在前，主要業務資料接續，輔助欄位其後，建立與更新時間置於最後。
4. 檢查 NULL、預設值、唯一性、索引、外鍵與刪除／更新行為是否符合既有程式碼的讀寫假設。
5. 對可能破壞既有資料的變更，先檢查資料回填、雙寫、相容欄位或回復策略；資訊不足時先說明風險並詢問。
6. 使用專案既有方式驗證 migration 可套用，並確認 ORM 與 schema 定義沒有漂移。

## 交付檢核

- 所有受影響表格與欄位都有具體 COMMENT。
- 欄位順序符合核心優先與時間欄位置後的規則。
- 每一項約束都有對應的業務或程式碼依據。
- 涉及既有資料時，列出相容性、資料遷移與回復風險。
